**Review 1** — approved
GaussianHmm.Learning.cs is a line-for-line faithful port of GaussianHMM._init/_do_mstep (hmm.py 307-322, 340-387) and passes all 96 acceptance tests (FitParity 68, Init 17, Learning 11; full suite 707/707, rerun by me). I verified the implementation against the reference formula-by-formula (means update; Spherical/Diag with the 1e-5 denominator floor and the mean-over-features; Tied with cvweight=max(covarsWeight-nf,0) and the summed posts denominator; Full with per-state denominators; the scalar CovarsPrior added to every entry including off-diagonals; means updated before covars), checked the oracle data directly (8 fit cases per file, no min_covar key in any constructor, the tied 'priors' case uses params 'stmc'), confirmed the coder commit touched only the writable file, and inspected the merged support (NeedsInit warnings, Covars setter copy+validate, NFitScalars for Aic/Bic). The pilot already ruled on Q1 by commit 143e4f7 (dropping the Full statistical-recovery case), which I accept: the Full M-step stays pinned exactly by the 16 Full oracle fit cases. One minor remark: dead helper methods in the locked InitTests.cs.

| Criterion | State | Comment |
|---|---|---|
| C1 | satisfied | All 64 oracle fit cases (8 per file x 4 files x Log+Scaling) pass, plus the 4 hand-made pins. The implementation matches _do_mstep line by line: base first; Means[c,f] = (MeansWeight*MeansPrior + Obs[c,f])/(MeansWeight + Post[c]); Spherical/Diag c_n with c_d = max(CovarsWeight-1,0)+Post[c] floored at 1e-5 and Spherical as the mean over features; Tied/Full c_n with the outer terms and cvweight = max(CovarsWeight-nf,0), Tied over the summed posts, Full per state; CovarsPrior is a scalar added to EVERY entry (off-diagonals included), exactly as numpy's scalar+matrix broadcast does; covars use the means as just updated. The oracle cases pin the priors (covars_prior=0.5, covars_weight=4.0, means_prior=1.0, means_weight=2.0 in the 'priors' case of all four files, including the single Tied/Full matrices), the parameter subsets (m, mc, st), structural zeros (left-to-right-keeps-zeros) and length-1 sequences (unit-sequences). Stated test assumptions hold: no oracle constructor carries a min_covar key (the test hardcodes the constructor default 1e-3), the tied 'priors' case uses params 'stmc' (so the caller-arrays test is valid), and the direct-DoMStep pin tests compute every expected value in code from the test's own inputs (ExpectedMeans/ExpectedCovars loops, Math.Max floors), never retyped. |
| C2 | satisfied | All 17 Init tests pass. Init runs base.Init first, then only for the letters that need it: Means = KMeans.Fit(x, NComponents).Centers under NeedsInit('m', 'means_', Means != null), Covars = data covariance (sample covariance of the columns, dividing by n-1, zeros for a single row, MinCovar on the diagonal) distributed by InternalUtils under NeedsInit('c', ...). Reproducible for a fixed RandomState (the merged BaseHmm.Init re-seeds new Random(seed) on each call) and different for another; explicit parameters keep their exact reference when InitParams does not name them; the merged NeedsInit raises one 'will be overwritten' warning per set parameter named by InitParams (4 for 'stmc' with all set, 1 for 'mc' with only means set), matching the ticket. KMeans is the merged, documented deterministic substitute for sklearn's KMeans ('not meant to reproduce its results'); the criterion and its tests compare against KMeans.Fit itself, and the oracle fits never reinitialize (InitParams = ''), so no parity gap is introduced. |
| C3 | satisfied | All 11 Learning tests pass. From a random Init, fits recover the true means (per-feature bound 1.5, best permutation over the 6 label orderings) and covariances (absolute bound 0.75 through FullCovars) for Spherical, Diag and Tied with fixed seeds; the log likelihood never decreases across 40 single-iteration Fits for all four types (Log implementation; Scaling parity for full fits is covered by C1's 64 oracle cases); Aic/Bic equal -2*Score + 2k and -2*Score + k*ln(rows) with k the sum of GaussianEmission.NFitScalars, which I verified against the documented counts for all four types (s: nc-1, t: nc(nc-1), m: nc*nf, c: nc / nc*nf / nc*nf*(nf+1)/2 / nf*(nf+1)/2). The Full statistical-recovery case was removed by the pilot's own commit 143e4f7 in answer to the coder's dispute (Q1): with the global data covariance as every state's initial full covariance, EM can merge two clusters (5 of 20 nearby seeds) - behaviour inherited from the reference, not a port defect. I accept this: the Full M-step remains pinned exactly by the 16 Full oracle fit cases, including the scalar-prior-on-every-entry quirk. |
| C4 | satisfied | Four short single-purpose private helpers plus the two overrides; no dead code in the src file; both protected members keep the stub XML summaries and I checked them against the code (formulas, the 1e-5 floor, the scalar-prior quirk, the updated-means ordering all match). Signatures are unchanged, no abstract member added, no new package (no csproj change). The coder's commit 4048ed3 modified only src/HmmLearn/GaussianHmm.Learning.cs (149 insertions, 2 deletions), exactly the writable scope; the working tree is clean. Caller arrays are never mutated: UpdateMeans and the covars updates allocate new arrays, the Covars setter (merged) validates and copies, and the base DoMStep allocates new StartProb/TransMat - confirmed by the caller-arrays test. |
