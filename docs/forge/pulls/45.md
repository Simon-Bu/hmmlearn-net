**Remarks**
- **R1** (blocking) `src/HmmLearn/GmmHmm.cs:84` — The XML summary of MinCovar was changed from the stub's accurate text ('Floor added to the diagonal of the data covariance when the covariances are initialized') to 'Floor on the diagonal of the covariance matrices (added on the diagonal when a Cholesky factorization fails in the sampling)', which describes behaviour that does not exist in this port: MinCovar is unused in GmmHmm.cs, the sampling path has no Cholesky retry, and the Cholesky retry in Stats.cs uses its own hardcoded 1e-7 constant, not the model's MinCovar. It also contradicts the sibling GaussianHmm.MinCovar summary, which matches how the codebase actually uses the property. Expected: A summary matching the behaviour, e.g. the original stub text: the floor is added to the diagonal of the data covariance when the covariances are initialized (Init, ported in the next ticket); the property is stored for now.
- **R2** (minor) `src/HmmLearn/GmmHmm.cs:575` — CheckCovarianceMatrix decides 'negative' vs 'null' eigenvalue with the tolerance 1e-8 + 1e-5*maxAbs: a smallest eigenvalue of -1e-10 (mathematically indefinite) raises the 'null eigenvalue' warning instead of the 'not positive definite' throw of hmmlearn's strict min_eigvalsh < 0, and a smallest eigenvalue of +1e-9 (strictly positive) raises the warning where hmmlearn's strict == 0 would stay silent. The allclose-style tolerance is the codebase convention (the symmetry check, CheckSum1), all locked tests pass, and a strict == 0 on computed eigenvalues is numerically meaningless, so this is accepted as the most reasonable reading. Expected: Nothing to change; noted for the record.
