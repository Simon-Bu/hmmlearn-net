**Review 1** — approved
The fit half of AbstractHmm is a faithful port of hmmlearn 0.3.3 base.py (fit 453-500, _needs_init 523-533, _check_and_set_n_features 535-543, _check_sum_1 556-565, _initialize_sufficient_statistics 646-668 and the accumulate variants from 670), adapted to the C# house conventions exactly as the ticket prescribes. Fit validates observations and lengths before Init and Check, hands the current Tol/NIter/Verbose to the monitor and resets it, runs E-step, lower bound, M-step and Report per iteration with the M-step of the converging iteration already run (the reference's XXX-annotated ordering), warns on zero-sum transmat rows after each non-converged iteration, and unsubscribes from Monitor.Warning in a finally block. The E-step dispatches on Implementation, uses the Fit* virtuals, and accumulates NObs, Start (first-sample posteriors) and the xi sums (scaling direct, log via exp) with the reference's 's'/'t' gating and length>1 guard. I re-verified every criterion against the reference file and the oracles, traced the ConvergenceMonitor semantics against the warning tests, and re-ran the full suite independently: 339/339 pass (log .factory/out/review-verify.log), consistent with the orchestrator's class-level verifications. Scope respected: the coder commit touches only the two writable files, the test commit only the four locked test files, working tree clean. The pilot's Q1 (CheckSum1 message culture) is resolved by the code: invariant culture, which is what the reference's Python formatting produces; the test accepts either rendering and pins the rest. No blocking remarks; two cosmetic wording items (R1, R2). No test disputes.

**Remarks**
- **R1** (minor) `src/HmmLearn/AbstractHmm.Fit.cs:290` — CheckSum1's matrix message renders the row sums comma-joined in the invariant culture ('[1, 0.8]'); the reference's numpy str() of the row-sum array would render them space-separated ('[1. 0.8]'). FitHelperTests pins only the message prefix, so nothing conflicts. Expected: Either rendering is acceptable for this ticket; if a later ticket tightens the full message, align it with the numpy rendering or document the deliberate C# style. No change required now.
- **R2** (minor) `src/HmmLearn/AbstractHmm.Fit.cs:7` — The class-level summary says 'Every member added here is virtual or non-abstract'; the E-step helpers (DoEstep, FitSequenceLog, FitSequenceScaling, ValidateLengths, HasZeroRow, ExpMatrix) are private - technically non-abstract, but the phrasing reads as if every member were overrideable. The parenthetical makes the intent (no new abstract surface) clear, so this is purely a wording nit. Expected: A phrasing such as 'no abstract member is added (earlier-acceptance subclasses keep compiling)' would be more precise. No change required now.
