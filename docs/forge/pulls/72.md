**Remarks**
- **R1** (blocking) `src/HmmLearn/MultinomialHmm.cs:27` — The new phrase 'every sample must total it (else ArgumentException)' promises an exception without limiting it to Fit. MultinomialHmm.CheckAndSetNFeatures enforces this only through BaseHmm.Init during Fit. AbstractHmm.Score, ScoreSamples and Decode call CheckObservations and Check instead; neither checks NTrials, and ComputeLogLikelihood uses the row's own total. For example, a valid one-state model with NTrials = 5 and emission probabilities [1/3, 1/3, 1/3] accepts Score([[1, 1, 1]]) and returns a finite score. The bundled reference follows the same inference path. The locked mismatch acceptance test exercises only Fit, so passing tests cannot establish the broader exception promise. Expected: Keep the fix documentation-only. Qualify the exception as a Fit validation, and make the constructor/property wording clear that inference uses each row's total. Preserve the documented null/free-totals and sampling contracts. Do not change code or locked acceptance tests.
