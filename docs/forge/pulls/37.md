**Remarks**
- **R1** (blocking) `src/HmmLearn/GaussianEmission.cs:222` — The PSD eigenspace fallback (the path GenerateSample takes when a state covariance is not positive definite, as specified by the stub's XML: 'if the matrix is not positive definite (but is positive semi-definite), a factor from its symmetric eigen decomposition, negative eigenvalues taken as 0') is mathematically wrong in two independent ways, so on that path the sample is NOT drawn from the Gaussian of the state and the XML summaries do not match the behaviour. (1) EigenspaceFactor (L209-225) builds factor[i,j] = sqrt(clip(lambda_i, 0)) * EigenVectors[j,i], i.e. F = D^{1/2} V^T; MathNet stores eigenvectors as the columns of EigenVectors (its own XML docs: 'column corresponding to real eigenvalue represents real eigenvector'; a = V D V^T). Since V is orthogonal, F*F^T = D^{1/2} V^T V D^{1/2} = D, the eigenvalue diagonal (negatives clipped), not a. Worked example: a = [[1, 0.5], [0.5, 1]] with eigenvalues 0.5 and 1.5 gives F*F^T = [[0.5, 0], [0, 1.5]] != a. The summary's claim 'L L^T = a' (L206) is false; the same conclusion holds even under the opposite rows-convention, so the bug does not depend on which convention MathNet actually uses. (2) Even a correctly oriented dense factor would be mis-multiplied: GenerateSample's product loop (L151-157) sums only k = 0..i, which is correct only for the lower-triangular Cholesky factor; for the dense eigenspace factor it drops the k > i terms, so the actual sample covariance is the triangular product (in the example [[0.25, 0.433], [0.433, 1.5]], wrong again). The path is unreachable through the public API - the Covars setter enforces strict positive definiteness for Full/Tied (ValidateCovars plus IsPositiveDefinite) and strictly positive variances for Spherical/Diag, so the naive Cholesky never fails for a settable model - which is why all C3 sampling tests pass; but the stub's XML (the ticket's stated specification) requires this fallback to work, and the ticket says GaussianEmission is reused later by the variational Gaussian model, where a PSD state covariance is a realistic input. Expected: Make the eigenspace path produce the (possibly degenerate) Gaussian of the state: (a) in EigenspaceFactor build L = V D^{1/2} with negative eigenvalues clipped to 0, i.e. factor[i,j] = EigenVectors[i,j] * sqrt(max(EigenValues[j].Real, 0)) - scale by column j, not by row i - so that L*L^T = V D V^T = a; (b) in GenerateSample compute x = mean + L*z with the full product over all k (a full product is also correct for the lower-triangular Cholesky factor, so the k <= i restriction can be dropped for both paths, or kept only on the Cholesky path). For the example a = [[1, 0.5], [0.5, 1]], the fixed factor L = [[0.5, 0.8660], [-0.5, 0.8660]] satisfies L*L^T = a exactly. Then the EigenspaceFactor summary ('L L^T = a') and the GenerateSample summary ('drawn from the Gaussian of state', including the PSD fallback) match the behaviour.
