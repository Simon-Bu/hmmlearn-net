**Remarks**
- **R1** (minor) `src/HmmLearn/Hmmc.ViterbiXi.cs:46` — Inconsistent, undocumented behaviour on consistently empty input (all four matrices (0, nc), i.e. n_samples = 0): ComputeScalingXiSum runs its documented empty loop and returns the neutral all-zeros matrix, while ComputeLogXiSum reads fwdlattice[ns - 1, 0] = fwdlattice[-1, 0] at line 46 and throws ArgumentOutOfRangeException — an exception type the stub never documents (it promises 'shape mismatch' ArgumentException for shape errors, and ns = 0 with matching columns is not a shape inconsistency). The C++ reference has unsigned underflow/undefined behaviour at the same spot, so the port neither improves nor degrades the reference, and no criterion, constraint, locked test or golden case covers n_samples = 0 — hence minor, not blocking. Expected: The two sibling functions share one consistent, documented behaviour for n_samples = 0, decided with Q2 (restating the tests agent's Q1): either ComputeLogXiSum also returns the neutral all -infinity matrix (a guard before the logProb read at line 46, matching the documented empty sum), or both functions throw a documented ArgumentException 'shape mismatch' for 0 samples with the stub XML updated accordingly. As written, one function silently returns a matrix while the other throws an undocumented exception type for the same input.
