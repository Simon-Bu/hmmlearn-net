**Review 1** — approved
MultinomialHmm is a faithful, spec-conformant port of hmmlearn 0.3.3 MultinomialHMM + BaseMultinomialHMM. Same-family waiver applied: I verified every criterion myself - re-ran all four verify commands plus the full suite (InferenceParityTests 11/11, FitParityTests 13/13, ValidationTests 11/11, SamplingAndFitTests 9/9, full suite 509/509), re-read the code line by line against the stub spec and the Python reference (hmm.py 812-943, _emissions.py 310-369, base.py fit/check flow), and independently recomputed the oracle assumptions (AIC = -2*score + 2*9 and BIC = -2*score + 9*ln(30) match the golden values exactly for all four fit cases, including emission-only; the constructor dicts indeed omit the Dirichlet priors). Scope is respected: git diff shows only src/HmmLearn/MultinomialHmm.cs plus the four locked acceptance test files, no csproj change, only MathNet.Numerics used. The code does not mutate caller arrays (the M-step copies Obs before normalizing, Init replaces with a new array), every public/protected member keeps an accurate XML summary, and the only behavioral deviations from Python are the ones the stub spec and the oracle README prescribe (rows of emissionprob must sum to 1; a zero Obs row stays zero in the M-step; NTrials null means free totals, enforced only by Sample throwing InvalidOperationException). No blocking or minor remarks. One non-blocking question restates Q1 with new evidence: the oracle generator (gen_oracle.py) documents that the port intentionally accepts varying totals when NTrials is unset, and Python only rejects n_trials=None on the score path (its fit flow infers per-sample totals in _init before _check), so the implemented behavior is the only reading under which the oracle's free-totals cases are runnable.

| C1 | satisfied | All three oracle inference cases (five-trials-two-sequences, one-trial-is-categorical, trial-counts-vary-per-sample) reproduce with both implementations for Score, ScoreSamples (log_prob + posteriors), Decode Viterbi (log_prob + states), Decode MAP, Predict and PredictProba within rtol 1e-6 / atol 1e-12. The five hand-rolled facts lock the formula's edge cases with operands from the tests' own inputs: a zero-count sample has likelihood exactly 1 and log likelihood exactly 0 under every state (0! / prod 0! * prod p^0, 0^0 = 1); the likelihood equals the multinomial formula computed with integer factorials on powers of two; one trial reduces to the categorical emission probability; the log likelihood handles 0*log(0) = 0 (finite, equals the log of the likelihood) and gives exactly -infinity for a positive count on a zero probability; and it stays finite and equal to the GammaLn formula where the direct product underflows (5000/5000 counts). I re-ran the verify command: 11/11 passed. I re-ran the verify command: 13/13 passed. |

CheckAndSetNFeatures also rejects NaN (NaN != Math.Truncate(NaN)). I re-ran the verify command: 11/11 passed. |
| C4 | satisfied | Sample returns 5000 count vectors that are non-negative integer vectors summing to exactly NTrials, with every state in range and at least 1000 samples per state; the per-state mean count of each feature is within 5 standard deviations of NTrials*p using the standard independent-samples bound sqrt(NTrials*p*(1-p)/m_s) - valid because the deliberately uniform transmat makes every sample's state i.i.d. with probability 1/2, and every operand of the bound comes from the test's own inputs. Sample is reproducible with a fixed Random and with a fixed RandomState; GenerateSampleFromState counts exactly NTrials independent categorical draws (verified on a degenerate row over 100 seeds). I re-ran the verify command: 9/9 passed. |
