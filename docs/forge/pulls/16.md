**Remarks**
- **R1** (minor) `src/HmmLearn/ConvergenceMonitor.cs:90` — A delta of exactly -0.0 (previous value +0.0, reported value -0.0, both legal IEEE doubles) is treated as non-negative because -0.0 >= 0.0 is true in IEEE comparison, so FormatLine prepends '+' and the delta column renders '+-0.00000000' (.NET 9 F8 keeps the sign of -0.0), whereas the Python template {delta:>+16.8f} prints '-0.00000000' for the same input. The input never occurs in oracle/golden/monitor.json, no criterion covers it, and the code follows the pilot-approved Q1 approach (F8 plus manual '+' prefix), so this is a note for the record, not a violation of any criterion, constraint or scope. Expected: No change required for this ticket. If the corner is ever exercised by a future scenario, either test for the sign bit (double.IsNegative) when choosing the '+' prefix or document the divergence; the locked acceptance tests and the oracle do not depend on it.
