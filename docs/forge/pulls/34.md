**Remarks**
- **R1** (minor) `src/HmmLearn/KMeans.cs:146` — The empty-cluster recovery picks the sample farthest from the emptied center's current position. The ticket prose ('the sample that is farthest from the center it is currently assigned to') most naturally measures each sample's distance to the center that sample is itself assigned to (the scikit-learn rule), while the stub's XML comment ('farthest from its own center'), which the ticket designates as the specification, supports the implemented reading with 'its' referring to the emptied center. The choice is documented in Move's summary, and the locked test A_center_left_without_samples_is_recovered was deliberately written to pass under every reading, so no criterion is violated; the two rules can only diverge on data where a cluster becomes empty, and the final state is consistent either way. Expected: Keep the implemented rule, or, if the pilot prefers the scikit-learn reading, measure each sample's distance to the center it is currently assigned to when picking the sample taken by an emptied center. Either way, keep the rule documented in the XML summary.
- **R2** (minor) `src/HmmLearn/KMeans.cs:20` — Fit's public XML summary (inherited verbatim from the stub) lists ArgumentException for x without rows or columns, NaN or infinity, and k out of range, but the implementation also throws for maxIter below 0 (Validate, lines 59-60), which the ticket's interface requires and the tests check. The summary is incomplete with respect to the behaviour. Expected: Extend the Throws line of Fit's summary to mention maxIter below 0.
