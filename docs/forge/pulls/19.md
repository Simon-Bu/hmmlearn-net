**Review 1** — approved
Independently verified the inference half of AbstractHmm against the ticket, the reference port (hmmlearn 0.3.3 base.py lines 129-398, 508-521), the oracle golden file, and the full repo, then re-ran every verify command myself: ScoringTests 16/16, DecodingTests 9/9, SamplingTests 12/12, ConstructionTests 12/12, and the full suite 297/297, all with exit code 0 (first build showed only four xUnit2020 warnings from the locked test helper, no failures). The port matches the reference semantics: Score is one forward pass per sequence summed over sequences; ScoreSamples is forward + backward with per-row log-normalization (Log) or row normalization (Scaling) and posteriors concatenated in sequence order; PredictProba/Decode wrap it; Viterbi always runs in log space via Hmmc.Viterbi with first-max tie-break; MAP takes the per-sample argmax posterior with log_prob as the sum of the largest posterior per sample (the hmmlearn quirk, confirmed against the golden value 4.068032310391702 for the wikipedia case); Sample validates nSamples and currState, draws the first state from StartProb or uses currState, then draws transitions from the previous row of TransMat via cumulative 'first index where cdf > u', and uses a fresh Random seeded from the RandomState property per call, exactly as the locked acceptance tests assume and as the reference's int-seed path does through check_random_state. Check order is CheckIsFitted -> Check -> CheckObservations everywhere the spec requires it; CheckObservations rejects empty, zero-column, NaN and infinite observations; SplitXLengths yields ArgumentException for lengths that do not sum to the rows or contain negatives; no caller array is mutated (traced every path and covered by a dedicated test); only the BCL is used, no package was added, no public/protected signature changed, no abstract member added, every public and protected member carries an XML summary that matches its behaviour, and there is no dead code. The change set is exactly src/HmmLearn/AbstractHmm.cs plus the four acceptance test files named in the ticket. The four pilot assumptions hold in the test code (per-class nested stubs whose ComputeLogLikelihood returns a copy of x and whose GenerateSampleFromState returns the state as a single observation, statistical bounds computed in code from the test's own StartProb/TransMat and observed departure counts, fixed seeds, and a fresh Random per call for the RandomState seed, consistent with the reference). No criterion fails, no constraint is violated, and nothing exceeds scope; the only observations are cosmetic (the xUnit2020 warnings above, in the locked test helper, and a NullReferenceException when a model has StartProb set but TransMat null, which mirrors the reference and is outside the ticket's specified checks), so there are no remarks to raise.
