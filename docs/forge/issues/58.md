# HMM-22 — VariationalGaussianHmm - M-step of the means and covariances

> Forgejo issue #58 · closed · opened 2026-10-08 08:00:42 UTC by `claude` · closed 2026-10-08 09:02:54 UTC  
> Labels: `state/merged` · Milestone: J4

**Spec (authoritative):** [`.factory/tickets/HMM-22.yml`](https://github.com/Simon-Bu/hmmlearn-net/blob/main/.factory/tickets/HMM-22.yml)

**Objective.** Complete VariationalGaussianHmm with the M-step of the means ("m") and the covariances ("c") of the four covariance types (port of
VariationalGaussianHMM._do_mstep of hmmlearn/vhmm.py): the class gets its DoMStep override in the new partial file
src/HmmLearn/VariationalGaussianHmm.Learning.cs (committed as a stub whose body already calls the base update and throws
NotImplementedException only when 'm' or 'c' is in Params). With it the model fits end to end and reproduces every fit case of the
oracle.
Reference: reference/hmmlearn-0.3.3/src/hmmlearn/vhmm.py lines 697-784 (_do_mstep); its tests
reference/hmmlearn-0.3.3/src/hmmlearn/tests/test_variational_gaussian.py; and the numbers of oracle/golden/variational_gaussian_<type>.json
(spherical, diag, tied and full; structure in oracle/README.md; do not open the JSON files whole, they are large).

**Criteria**

- **C1** — Fit reproduces the six posterior arrays, covars, startprob, transmat, history, n_iter_done, converged and score of every fit case of
the four oracle files (spherical, diag, tied, full) with both implementations (all of stmc, stm without covars, st, ten and up to a
hundred iterations).
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm22.FitParityTests`

- **C2** — DoMStep on hand-made statistics updates exactly the arrays of the letters in Params: 'm' sets BetaPosterior and MeansPosterior, 'c' sets
DofPosterior, ScalePosterior and Covars for each of the four covariance types (values from the formulas, tied sums over the states,
spherical averages over the features), uses the new means when both letters are given and the stored ones when only 'c' is given, and
leaves the arrays of the other letters alone.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm22.MStepTests`

- **C3** — The lower bound never decreases during Fit for each covariance type (single-iteration fits from k-means initialization with a fixed seed,
both implementations); the full, tied, diag and spherical models agree on the parameters they share when the data are isotropic;
a fit with only 'c' or only 'm' in Params runs and changes only its arrays.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm22.FitBehaviourTests`

- **C4** — The code stays readable: short methods (one helper per covariance type), no dead code, the XML summary matches the behaviour. · judged by the reviewer

**Roles.** tests: `qwen-q4-long` · coder: `qwen-pi` · reviewer: `qwen-q4-long` · 1 rounds at most

**Writable scope.** `src/HmmLearn/VariationalGaussianHmm.Learning.cs`

**Waiver: reviewer from the same family as the coder.** POC local-only decided by Simon
