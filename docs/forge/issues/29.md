**Review remarks left open**
- [ ] **R1** (minor) `src/HmmLearn/CategoricalHmm.cs:54` — The random emission init creates a fresh generator (new Random(RandomState.Value) or Random.Shared) on each Init call, so with a given seed the emission draws start from the same stream position as the startprob draws and a second Fit with InitParams containing 'e' re-initializes to the identical emission matrix. The Python reference (hmm.py _init) instead continues the model's single random state, so a second init would draw different values. This is not a spec violation: the stub's Init summary prescribes 'the same seeding rule as the base' and the read-only BaseHmm documents 'a new generator at each call', and all acceptance tests (which require determinism per seed, not a shared stream) pass. Recorded so the deliberate deviation from the reference is on file; it would only matter if a future ticket requires bit-identical initialized parameters to Python under one shared seed. Expected: No change required for this ticket unless the pilot rules otherwise (see Q1); if single-stream parity with Python is ever required, the fix belongs to the base seeding rule (BaseHmm.Init) or to a follow-up ticket, since BaseHmm.cs is read-only here.
