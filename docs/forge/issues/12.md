# HMM-5 — Hmmc xi sums and Viterbi

> Forgejo issue #12 · closed · opened 2026-10-07 15:34:31 UTC by `claude` · closed 2026-10-07 16:11:46 UTC  
> Labels: `state/merged` · Milestone: J1

**Spec (authoritative):** [`.factory/tickets/HMM-5.yml`](https://github.com/Simon-Bu/hmmlearn-net/blob/main/.factory/tickets/HMM-5.yml)

**Objective.** Port the xi sums and the Viterbi algorithm of ext/_hmmc.cpp to C#: HmmLearn.Hmmc.ComputeScalingXiSum, ComputeLogXiSum and Viterbi
(second file of the partial class Hmmc; the forward and backward passes and the log helpers LogSumExp and LogAddExp are already
merged in Hmmc.ForwardBackward.cs and can be called). The EM M-step and the decoders use them.
Reference: reference/hmmlearn-0.3.3/ext/_hmmc.cpp lines 207-322 (compute_scaling_xi_sum, compute_log_xi_sum, viterbi); the
Wikipedia example of reference/hmmlearn-0.3.3/src/hmmlearn/tests/test_base.py (test_do_viterbi_pass); and the numbers of
oracle/golden/hmmc.json (structure in oracle/README.md; do not open the JSON file whole, it is large).

**Criteria**

- **C1** — Hmmc.ComputeScalingXiSum reproduces scaling_xi_sum of every case of oracle/golden/hmmc.json that has one (including the single
sample case, which gives zeros) and throws ArgumentException for inconsistent shapes.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm5.ScalingXiSumTests`

- **C2** — Hmmc.ComputeLogXiSum reproduces log_xi_sum of every case that has one (including entries equal to -infinity and the single
sample case) and throws ArgumentException for inconsistent shapes.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm5.LogXiSumTests`

- **C3** — Hmmc.Viterbi reproduces log_prob and states of the cases of oracle/golden/hmmc.json whose name does not start with "viterbi-"
(including the Wikipedia example [0, 0, 1, 0, 0] with log probability -4.4590 and the impossible observation), and throws
ArgumentException for inconsistent shapes.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm5.ViterbiTests`

- **C4** — Hmmc.Viterbi breaks ties like the C++: final state = first maximum, earlier states = largest index among equal maxima. The cases
"viterbi-ties" and "viterbi-partial-ties" of oracle/golden/hmmc.json are reproduced.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm5.ViterbiTieBreakingTests`

- **C5** — The code stays readable: short methods, no dead code, the XML summaries match the behaviour. · judged by the reviewer

**Roles.** tests: `qwen-q4-long` · coder: `qwen-pi` · reviewer: `qwen-q4-long` · 1 rounds at most

**Writable scope.** `src/HmmLearn/Hmmc.ViterbiXi.cs`

**Waiver: reviewer from the same family as the coder.** POC local-only decided by Simon
