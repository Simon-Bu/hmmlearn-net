# HMM-8 — AbstractHmm fit - EM loop, E-step and sufficient statistics

> Forgejo issue #21 · closed · opened 2026-10-07 18:04:43 UTC by `claude` · closed 2026-10-07 19:13:39 UTC  
> Labels: `state/merged` · Milestone: J1

**Spec (authoritative):** [`.factory/tickets/HMM-8.yml`](https://github.com/Simon-Bu/hmmlearn-net/blob/main/.factory/tickets/HMM-8.yml)

**Objective.** Port the fitting half of _AbstractHMM of hmmlearn/base.py to C#: AbstractHmm.Fit (the EM loop), the E-step, the base sufficient
statistics, the hooks that models override (Init, EstepBegin, InitializeSufficientStatistics, AccumulateSufficientStatistics,
DoMStep, ComputeLowerBound, and the "fit" variants of the start probabilities, transition matrix and likelihoods) and the helpers
NeedsInit, CheckAndSetNFeatures and CheckSum1, plus the data holder SufficientStatistics. The inference half (Score, Decode,
Sample, posteriors) is already merged in AbstractHmm.cs. No concrete model exists yet: the M-step of BaseHmm comes later.
Reference: reference/hmmlearn-0.3.3/src/hmmlearn/base.py lines 453-500 (fit), 502-506, 523-566 (_needs_init,
_check_and_set_n_features, _get_n_fit_scalars_per_param, _check_sum_1), 646-778 (_initialize_sufficient_statistics,
_accumulate_sufficient_statistics and its scaling and log variants, _do_mstep, _do_estep, _estep_begin, _compute_lower_bound) and
873-889 (BaseHMM._fit_scaling and _fit_log, which here live once in AbstractHmm); the numbers of oracle/golden/hmmc.json and
oracle/golden/base.json (structure in oracle/README.md; do not open the JSON files whole, they are large).

**Criteria**

- **C1** — Fit runs Init, Check, then at most NIter iterations of E-step, ComputeLowerBound, DoMStep and Monitor.Report, stopping after the
iteration where Monitor.Converged becomes true (the M-step of that iteration has run); NIter = 0 only initializes and checks;
the monitor receives Tol, NIter and Verbose and is reset at the start of each Fit; Monitor.History holds the lower bounds; Fit returns
the same instance; lengths null means one sequence; lengths that do not sum to the number of rows, or invalid observations, throw
ArgumentException before Init runs.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm8.FitLoopTests`

- **C2** — The statistics given to DoMStep match the oracle for both implementations: NObs is the number of sequences, Start the sum of the
first-sample posteriors, Trans the sum of the xi sums (sequences of length 1 add nothing to Trans), each filled only when 's' (resp.
't') is in Params; the lattice given to AccumulateSufficientStatistics holds probabilities with Scaling and log probabilities with Log;
the "fit" virtual members are used by the passes (a model overriding FitTransMat sees its matrix in the xi sums).
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm8.ExpectationStepTests`

- **C3** — SufficientStatistics starts at zeros of the right shapes; NeedsInit returns true when the letter is in InitParams (warning when the
parameter is already set) or when the parameter is not set, false otherwise; CheckAndSetNFeatures records the number of columns and
rejects a different one; CheckSum1 accepts sums equal to 1 within the numpy tolerance and throws ArgumentException otherwise, for
vectors and for the rows of matrices.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm8.FitHelperTests`

- **C4** — A warning raised by the monitor during Fit reaches the Warning subscribers of the model; a TransMat with a row that sums to 0 after
an iteration that did not converge raises the zero-sum warning; the monitor is unsubscribed when Fit ends, even when an exception
escapes.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm8.FitWarningTests`

- **C5** — The code stays readable: short methods, no dead code, the XML summaries match the behaviour. · judged by the reviewer
