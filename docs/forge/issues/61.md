# HMM-23 — InternalUtils - lengths sum without overflow and covariances without features

> Forgejo issue #61 · closed · opened 2026-10-08 09:54:44 UTC by `claude` · closed 2026-10-08 10:14:51 UTC  
> Labels: `state/merged` · Milestone: J5

**Spec (authoritative):** [`.factory/tickets/HMM-23.yml`](https://github.com/Simon-Bu/hmmlearn-net/blob/main/.factory/tickets/HMM-23.yml)

**Objective.** Fix the two gaps that the review of HMM-2 left open (follow-up issue #6) in src/HmmLearn/InternalUtils.cs, which is already merged:
1. SplitXLengths adds the lengths in an int. A sum that wraps around 2^31 can equal the number of rows, bypass the sum check and end in an
   undocumented exception or a huge allocation. The reference (numpy int64 cumsum, split_X_lengths in
   reference/hmmlearn-0.3.3/src/hmmlearn/_utils.py) raises ValueError there, so the port must throw the documented ArgumentException.
2. ValidateCovars throws IndexOutOfRangeException for a covariance without features: tied shape (1, 0, 0) or full shape (nc, 0, 0). The
   reference (_validate_covars, same file) accepts them: a 0 x 0 matrix is symmetric and has no eigenvalue to reject.
The coder writes the tests of this ticket and then the fix (no separate tests agent).

**Criteria**

- **C1** — SplitXLengths throws ArgumentException when the sum of the lengths is not the number of rows, even when the 32-bit sum wraps around to
the number of rows (lengths of 4 x 2^30 on 0 rows, lengths { int.MaxValue, int.MaxValue, 4 } on 2 rows); valid, negative and wrong-sum
inputs keep their documented results.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm23.SplitXLengthsOverflowTests`

- **C2** — ValidateCovars accepts covariances without features (tied (1, 0, 0), full (nComponents, 0, 0)) and keeps rejecting the shapes that do
not match nComponents with ArgumentException.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm23.ZeroFeatureCovarsTests`

- **C3** — The new tests are meaningful: each class has at least one test that fails on the unfixed code and passes on the fix (the reviewer
checks this against the diff and the coder's summary), and no new test re-implements the code under test.
 · judged by the reviewer

- **C4** — The XML summaries of the two methods state the new rules; the code stays readable: short methods, no dead code. · judged by the reviewer

**Roles.** coder: `sonnet-5.5` · reviewer: `gpt-sol-6.1` · 2 rounds at most

**Writable scope.** `src/HmmLearn/InternalUtils.cs`, `tests/acceptance/HMM-23/**`
