# HMM-27 — MultinomialHmm - document the free trial counts of NTrials

> Forgejo issue #71 · closed · opened 2026-10-08 10:37:17 UTC by `claude` · closed 2026-10-08 10:43:30 UTC  
> Labels: `state/merged` · Milestone: J5

**Spec (authoritative):** [`.factory/tickets/HMM-27.yml`](https://github.com/Simon-Bu/hmmlearn-net/blob/main/.factory/tickets/HMM-27.yml)

**Objective.** Close follow-up issue #32 (questions Q1 and Q2 of the review of HMM-11): MultinomialHmm.Check() does not reject NTrials == null, whereas
hmmlearn's MultinomialHMM._check raises ValueError("n_trials must be set"). The pilot read the reference (hmm.py, _emissions.py): the
difference is deliberate and must be written down, not removed.
- In hmmlearn the likelihood never uses self.n_trials: it takes the total of each row of X. Fit stores the per-sample totals in n_trials
  when it is None (_check_and_set_n_features), so that _check passes after a fit; a model whose parameters are set by hand needs any
  non-None n_trials. Only sampling needs a single value ("For sampling, a single n_trials must be given").
- In the port NTrials is an int?. A value means: every sample must total NTrials, and sampling uses it. null means: the totals are free,
  each sample's own total is its number of trials. That is a valid state for inference, for a fit (the totals may vary per sample) and for
  a model set by hand; only Sample needs a value (InvalidOperationException without it). Adding hmmlearn's check would break the
  free-totals path that the oracle cases trial-counts-vary-per-sample and trial-counts-inferred-and-varying cover.
Deliverable: the XML documentation of this contract, in src/HmmLearn/MultinomialHmm.cs, on the NTrials property, on the nTrials constructor
parameter and on Check(). No behavior change: the existing tests that lock the contract stay green. The coder makes the edit (no tests agent).

**Criteria**

- **C1** — The tests that lock the free-totals contract of the inference stay green: the oracle inference cases of MultinomialHmm, including
trial-counts-vary-per-sample (NTrials null).
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm11.InferenceParityTests`

- **C2** — The tests that lock the NTrials rules stay green: free totals in a fit, the total check when NTrials is set, no sampling without NTrials.
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm11.ValidationTests`

- **C3** — The XML documentation of the NTrials property, of the nTrials constructor parameter and of Check() states the contract above (null =
free totals, set = enforced total and used by Sample, no "n_trials must be set" check on purpose and why); every statement is true; no
code changed.
 · judged by the reviewer
