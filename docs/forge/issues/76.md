# HMM-29 — Hmmc - wording of the 0-sample result in the xi sum summaries

> Forgejo issue #76 · closed · opened 2026-10-08 10:52:05 UTC by `claude` · closed 2026-10-08 10:54:24 UTC  
> Labels: `state/merged` · Milestone: J5

**Spec (authoritative):** [`.factory/tickets/HMM-29.yml`](https://github.com/Simon-Bu/hmmlearn-net/blob/main/.factory/tickets/HMM-29.yml)

**Objective.** Close follow-up issue #67, the minor remark that the review of HMM-25 left open on its own XML text in src/HmmLearn/Hmmc.ViterbiXi.cs.
The summary of ComputeLogXiSum says "With 0 samples (all inputs (0, nc))", which wrongly includes transmat: the transition matrix is
(nc, nc) for 0 samples too. Say that fwdlattice, bwdlattice and logFrameprob are (0, nc) while transmat is (nc, nc). While there, make
the summary of ComputeScalingXiSum say the same for its own 0-sample result (an (nc, nc) matrix of zeros, as for one sample), so that the
two siblings are documented alike. Documentation only: no code, no test, no other file changes. The coder makes the edit (no tests agent).

**Criteria**

- **C1** — The tests that lock the 0-sample behavior stay green (no behavior change).
 · `dotnet run --project tests/HmmLearn.Tests -- --filter-class HmmLearn.Tests.Acceptance.Hmm25.ZeroSampleXiSumTests`

- **C2** — The XML summary of ComputeLogXiSum says that fwdlattice, bwdlattice and logFrameprob are (0, nc) and transmat is (nc, nc) for 0 samples;
the summary of ComputeScalingXiSum states its 0-sample result; every statement is true; only comments changed.
 · judged by the reviewer

**Roles.** coder: `sonnet-5.5` · reviewer: `gpt-sol-6.1` · 2 rounds at most

**Writable scope.** `src/HmmLearn/Hmmc.ViterbiXi.cs`
